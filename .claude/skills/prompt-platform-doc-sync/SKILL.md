# 存档文档同步规范

## 存档文件位置

```
docs/
├── database.sql   # 数据库所有表的 DDL 语句 + 变更历史
├── api.md         # 所有 API 接口定义（方法/路径/请求/响应）
└── pages.md       # 所有页面的组件树和路由设计
```

## 何时触发同步

当完成以下操作后，**必须检查**是否需要同步存档文档：

| 操作内容 | 需要同步的文档 |
|----------|--------------|
| 新增 / 修改 / 删除数据库表 | `docs/database.sql` |
| 新增 / 修改 / 删除 API 路由 | `docs/api.md` |
| 新增 / 修改 / 删除页面或路由 | `docs/pages.md` |
| 以上涉及的跨层变更 | 对应的多个文档 |

## 同步规则

### database.sql 同步规则

1. **新增表**：在对应 Phase 章节下追加完整 `CREATE TABLE` DDL
2. **修改表**：
   - 更新 DDL 到最新结构
   - 在"表变更历史"表格追加一条记录（日期 + 变更内容 + Phase + 迁移脚本名）
3. **删除表**：移除 DDL，在变更历史中记录
4. DDL 格式统一用 MySQL 语法，含索引和外键

### api.md 同步规则

1. **新增接口**：在对应 Phase 章节的表格中追加一行
2. **修改接口**：更新表格中对应行的方法/路径/请求/响应
3. **删除接口**：移除表格行
4. 变更后在"接口变更历史"表格追加记录
5. 请求/响应体有结构变化时，更新对应的 JSON 示例

### pages.md 同步规则

1. **新增页面**：在路由总表追加行 + 在对应 Phase 下补充组件树
2. **修改页面**：更新组件树，标注新增/移除/调整的组件
3. **删除页面**：移除路由和组件树
4. 变更后在"页面变更历史"表格追加记录

## 同步流程

```
1. 完成代码变更（如新增了一个 API 路由）
2. 识别变更类型 → 确定需要同步哪个文档
3. 读取对应 docs/ 文件
4. 按同步规则更新文档内容
5. 在变更历史表格追加记录
6. 确认文档与代码一致
```

## 注意事项

- 文档同步是代码变更的**必要收尾步骤**，不是可选操作
- 如果只改了业务逻辑（如表单校验规则）但表结构/接口/页面没变，不需要同步
- 变更历史日期格式：YYYY-MM-DD
- 每次同步只更新对应文档，不要动其他无关文档
